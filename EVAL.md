# Evaluation
- Offline tests (no network, no real DNS: the test module installs a deterministic resolver): `python -m unittest discover -s tests` (53 tests): organisation-number checksum, claim contract, identity gate (lookalike domains, location/legal-form/RDAP/privacy-page proofs), wrong-company rejection, network-down handling, per-company timeout, batch size invariants, refresh diffs, previous-snapshot seeding, unsafe URLs and DNS-rebinding guard, robots.txt failure modes, output-validator defects, malformed input/output files, timeout state isolation, budgets, viewer rendering.
- Live smoke test: `reports/` holds the 100-company batch (starter-kit selector, seed 20260823) and the run report/envelopes. The report states inputs, envelopes, distinct organisations, silent drops, contract issues, runtime, requests, cost and per-family hit rates.
- Pass criteria: envelopes == inputs == expected count, no duplicates, 0 contract issues, exit code 0.
- Precision audit: after the first smoke run, every published website was reviewed by name, municipality and match method; looser matches were removed (see IDENTITY_RESOLUTION.md). No hand-labelled gold set or recall measurement is included; hit rates are fractions of companies with at least one available claim in a family, not recall against the hidden reference.

## v1.5.0 measurement
`python run.py measure --file <envelopes> --inputs <manifest>` reports one-envelope-per-input accounting, duplicate envelopes, duplicate claim keys/evidence ids, evidence completeness, span rate, value-supported rate, entity-link consistency, dated-claim rate and per-family company coverage. These are **internal consistency checks, not an official score and not ground-truth accuracy**. Regression tests: `tests/test_reviewer_fixes.py` (28 of its 37 tests fail on the reviewed v1.2.1: `SIGNALPOST_SRC=<v1.2.1 src>`), `tests/test_platform.py`.
